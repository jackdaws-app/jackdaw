Version history

Publishing puts new text in front of readers immediately. It does not put it in git: the repository, the printed page, a reader with JavaScript off and the Chrome Web Store listing all keep showing the committed text until someone runs node site/policy-sync.js --write and commits the result. That gap is the safety property — a policy whose visible text depends on a network call is a policy that can be blank — but it is only safe while it is short, so the strip above reports it and this page will keep saying so until it closes.

Versions are append-only and per-deployment. Restoring an earlier version republishes its text under a new number rather than deleting anything, so what was live between any two dates stays answerable afterwards. The structure check below the editor mirrors the one the server applies at publish time; it exists to tell you at the moment of the mistake rather than after the page is live, and it is the server's answer that decides.
